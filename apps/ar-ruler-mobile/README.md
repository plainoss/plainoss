# AR Ruler Mobile

Native Android AR Ruler, built with Kotlin Multiplatform. The camera opens as soon as camera permission and Google Play Services for AR are available. Measurement math and state are shared Kotlin; Android owns the Compose Material 3 interface, ARCore session, camera rendering, and local storage.

The [web app](../web-ar-ruler) uses the TypeScript engine in `packages/core`. This app's Kotlin engine preserves equivalent geometry, units, and measurement behavior, with common Kotlin tests covering the same reference cases. Android and future iOS platform adapters share the Kotlin core.

## Build and install

Prerequisites:

- JDK 17 or 21. All app bytecode targets Java 17.
- Android SDK Platform 37 and current Android SDK command-line tools. Accept SDK licenses through Android Studio's SDK Manager or `sdkmanager --licenses`.
- A current Android Studio release for IDE support, or the checked-in Gradle wrapper for command-line builds. No globally installed Gradle is required.

Open `apps/ar-ruler-mobile` as a project in Android Studio. Point `ANDROID_HOME` at the Android SDK, or create an untracked `local.properties` containing `sdk.dir=/absolute/path/to/Android/sdk`. Select JDK 17 or 21 as the Gradle JDK.

From the repository root:

The `pnpm` Android shortcuts automatically find a compatible installed JDK 17 or 21 and an Android SDK in standard locations. A compatible explicit `JAVA_HOME` is respected. Direct `./gradlew` commands still need a compatible JDK selected and an SDK configured through the environment or `local.properties`.

```bash
# Shared Kotlin tests, Android lint, and installable debug APK
pnpm run android:check

# Build only
pnpm run android:build

# Install on an attached device with USB debugging enabled
pnpm run android:install
```

The native project also works without Node or pnpm:

```bash
cd apps/ar-ruler-mobile
./gradlew :shared:jvmTest :androidApp:lintDebug :androidApp:assembleDebug
./gradlew :androidApp:installDebug

# Compact/expanded controls, point editing, and area-closing UI tests on an emulator/device
./gradlew :androidApp:connectedDebugAndroidTest
```

On Windows, use `gradlew.bat` for the equivalent commands. The debug APK is written to `androidApp/build/outputs/apk/debug/androidApp-debug.apk`. The release application ID is `app.plainoss.arruler`; debug builds use `app.plainoss.arruler.debug` so they can coexist with a release; Android 8.0 (API 26) or newer is required.

The root pnpm/Turbo commands continue to build the web app and TypeScript packages. Native compilation runs separately. On every pull request and push to `main`, CI runs the shared tests, Android lint, and debug build, then uploads `ar-ruler-mobile-debug-apk` for 14 days. Open the workflow run in GitHub Actions, download that artifact from **Artifacts**, and extract `androidApp-debug.apk` to install it. The **Build Mobile APK Artifact** workflow also runs on `mobile-*` tags or manual dispatch and retains its APK for 30 days. These APKs use Android's debug signing.

CI also checks release lint, a bundle signed with a disposable test key, its manifest and signature, native ELF alignment and APK packaging generated by bundletool. It uses no signing secrets or Play credentials in PR jobs.

## Signed bundles and Play internal testing

The **AR Ruler Internal Release** workflow runs on Android-relevant changes merged to `main`, or manual dispatch from `main`. It repeats repository checks, builds with the upload key from the main-only `android-release` GitHub environment, and retains `ar-ruler-release-<run-id>` for 90 days. This contains the AAB, SHA-256 checksum, source/version/certificate metadata, verification report, and native symbols when available. Third-party prebuilt libraries may not provide symbols. Minification is currently disabled, so no R8 mapping is generated.

Play publishing stays paused while repository variable `PLAY_INTERNAL_ENABLED` is `false`. After the first Console upload, enable it to publish the verified bundle to `internal` with Gradle Play Publisher and keyless Google credentials. `PLAY_RELEASE_STATUS` starts as `draft`; switch to `completed` once the first internal release is installable.

For production, install and test the intended version from Play internal testing, then run **Publish AR Ruler to Production** on `main` in GitHub Actions with its exact version code. That manual action confirms your device checks; CI promotes the same bundle without rebuilding, using the original release notes. Google review still controls public availability. Merges never trigger production. The button requires one-time Console setup and `PLAY_PRODUCTION_ENABLED=true`; see the [production setup and recovery guide](../../docs/android-releases.md#publish-to-production-one-device-check-one-button).

For local signed builds, set `ANDROID_KEYSTORE_PATH`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, `ANDROID_UPLOAD_CERTIFICATE_SHA256`, `ANDROID_VERSION_CODE` and `ANDROID_VERSION_NAME`, plus `JAVA_HOME` and `ANDROID_HOME`, then run:

```bash
bash tools/release/build.sh /absolute/path/to/release-output
```

The output directory must be outside tracked source directories. Release builds fail without complete signing credentials. Do not use `--info`, `--debug`, build scans or configuration caching with real signing secrets. See the [release setup and recovery guide](../../docs/android-releases.md) for Console bootstrap, credentials, retries and device validation.

## Measurement workflow

1. Launch the app and allow camera access. If prompted, install or update Google Play Services for AR, then return to the app.
2. Slowly move the phone over a well-lit, textured surface until the aim indicator finds a point.
3. Tap the compact measurement result to expand details and choose Distance, Path, Area, or Angle. Aim at each point and press **+** to place it. Distance takes independent pairs of points; keep placing pairs to include several distances in one saved photo. Save is available when every pair is complete; Undo removes the latest endpoint, and Clear removes all pairs. Path connects a series of points, labels each segment and shows the total; Angle uses three points with the second point as its vertex. For Area, place at least three corners in order on one flat surface, then tap the first point or **Close area**. A translucent fill shows the polygon. After closing, **+** starts a new area.
4. In every mode, tap a placed point or expand details and tap its number in **Move point**, including points outside the camera view. Selecting a point collapses details so you can aim at its new position and tap **Move**. Tap **Cancel**, the selected point, or Back to cancel. Moving a corner keeps a closed area closed. Undo reopens a closed area before removing corners; otherwise it removes the last point. Clear starts over.
5. Change units without remeasuring. Save stays visible in the compact panel; expand details to copy a completed measurement. Saving a camera measurement also captures the camera view with measurement lines and the result. History shows photo previews; tap one to enlarge it. Rename records, delete individual saves or clear history including their photos. Settings offers history limits of 20 (default), 50, 100 or 200, with confirmation before trimming existing records. Use **Share photo** in history or the enlarged viewer to share the saved image and measurement overlay through the Android sharesheet. **Share text** shares the result without an image, including older records without photos. Tap the result again or press Back to collapse details.

Measurement details start collapsed, leaving more camera view visible. The original circular **+**, Undo and Clear controls float directly over the camera without a shared card background. The compact result panel is translucent; guidance and tracking warnings appear inside it instead of a large persistent camera overlay. Expanded details scroll on short displays.

Release builds provide camera measurements only and require an ARCore-supported camera device. The developer practice canvas, presets and grid snapping are available only in debug builds for development and automated testing; they are hidden from release settings, recovery screens and help.

ARCore measurements are estimates. Surface texture, lighting, motion, tracking quality, and distance affect accuracy. Moving the app to the background releases the camera; returning resumes the AR workflow.

| Capability                              | Android implementation                                                                                 |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Camera on launch                        | Starts automatically after required permission and AR service checks                                   |
| World-space measurement                 | Native ARCore hit tests, anchored points, live previews, and projected measurement lines               |

| Editing                                 | Reposition endpoints, undo the last point, or clear the measurement                                    |

## Modules and iOS extension

```text
ar-ruler-mobile/
├── androidApp/                  # Android app: Compose, ARCore, permissions, storage
├── shared/
│   └── src/
│       ├── commonMain/          # Portable geometry, units, measurement state
│       └── commonTest/          # Pure Kotlin tests, run using the host JVM target
├── gradle/libs.versions.toml    # Pinned dependency and plugin versions
└── gradlew                     # Checked-in wrapper with distribution checksum
```

The shared module uses the Android Kotlin Multiplatform library plugin, plus a JVM target for tests. It has no Android or ARCore dependencies in common code. Android UI and camera APIs stay out of that module.

When adding iOS, add Apple targets to `shared`, expose a framework to an iOS application, and implement an ARKit adapter with the same point-placement and measurement-state contracts. Keep camera permissions, session lifecycle, and platform interface behavior native. Apple targets are deliberately deferred so Android development and CI do not require Xcode.

Build dependencies are pinned to Kotlin 2.4.21, Android Gradle Plugin 9.5.0 (built-in Kotlin), Gradle 9.8.2, Compose BOM 2026.09.00, and ARCore 1.57.0. See the [Kotlin compatibility table](https://kotlinlang.org/docs/gradle-configure-project.html), [Android KMP plugin guide](https://developer.android.com/kotlin/multiplatform/plugin), and [ARCore Android documentation](https://developers.google.com/ar/develop/java).

## Device verification

Shared JVM tests and Android compilation cannot verify camera tracking or physical measurement accuracy. Before release, test on a [supported physical ARCore device](https://developers.google.com/ar/devices):

- First launch, granted permission, denied permission, and permanent denial followed by Settings recovery.
- Missing/outdated Google Play Services for AR and an unsupported Android device.
- Scanning, all four measurement modes, point placement, endpoint editing, undo/clear, and unit changes.
- Saved photos and overlay alignment in all four modes, portrait/landscape, rapid Save taps, backgrounding during capture, storage failure and tracking loss.
- History previews and enlarged photos, rename persistence, legacy records without photos, history-limit migration and trimming confirmation, oldest-record eviction, individual delete, clear confirmation, associated photo cleanup, copy, and Android text sharing.
- Confirm release settings and recovery screens contain no practice canvas or sample entry points. Test developer presets and grid snapping separately in debug builds.
- Home/app switching, screen rotation, screen lock/unlock, camera contention, and return from Settings.
- Dark/bright scenes, low-texture surfaces, tracking loss and recovery, and known reference lengths.
- Small and large displays, gesture navigation, large text, and TalkBack labels.

Initial installation or an AR service update may need network access. Measurement runs locally after the required AR service is installed.
